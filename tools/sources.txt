# 上游规则集清单——tools/sync-rules.py 的唯一数据来源。
#
# 顺序与策略映射以 Johnshall/lazy_group.conf（2026-08-18 导出）为基准，
# 但补回的源必须插在语义正确的位置而非堆在末尾——首次实现时堆在末尾，
# 导致 Bing/GoogleFCM/BiliBiliIntl/AppleID/AppleMusic 五项被前面的总集吞掉，
# 其中 bing.list 直接产出 0 条。
#
# 顺序即优先级：同一条规则只保留首个出现的策略，与 Shadowrocket 自上而下
# 的匹配语义一致。以下先后关系是硬约束，改动会造成功能性回归：
#   细分苹果集 < Apple 总集      BiliBiliIntl < BiliBili
#   AI 各集    < Twitter/Global  Bing < Microsoft
#   GoogleFCM  < Google          SteamCN < Steam
#
# 三处刻意偏离 lazy_group，均有实测依据：
#   1. 保留广告拦截四源——它完全没有
#   2. SteamCN 归全球直连而非游戏平台——后者代理优先，会拖进几十 GB 下载
#   3. 补回它未覆盖的源——否则对应分组变成无规则的孤儿组
