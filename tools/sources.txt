# 上游规则集清单——tools/sync-rules.py 的唯一数据来源。
#
# 顺序与策略映射以 Johnshall/lazy_group.conf（2026-08-18 导出）为基准，
# 但补回的源当初必须插在语义正确的位置而非堆在末尾（那时本文件顺序决定去重）——首次实现时堆在末尾，
# 导致 Bing/GoogleFCM/BiliBiliIntl/AppleID/AppleMusic 五项被前面的总集吞掉，
# 其中 bing.list 直接产出 0 条。
#
# 本文件的顺序不决定优先级（见下方「2026-09-24 起」一段）：跨策略的先后由
# config/default.conf [Rule] 里 RULE-SET 的顺序决定，本文件只决定同一策略内
# 多个上游的先后。以下先后关系是硬约束，在 [Rule] 里颠倒会造成功能性回归
# （以 check-config.py 的 ORDER 为准，这里只是摘要）：
#   AppleMusic/TV (apple-media) < Apple   BiliBiliIntl < BiliBili
#   AI 各集 < Google/Microsoft/Twitter/Global   Bing < Microsoft
#   SteamCN (direct-global) < Steam (game)
# 已不再是约束的：GoogleFCM 与 Google 同属 📢 谷歌服务、AppleID 与 Apple 同属
# 🍎 苹果服务，同策略内先后不影响分流。
#
# 三处刻意偏离 lazy_group，均有实测依据：
#   1. 保留广告拦截四源——它完全没有
#   2. SteamCN 归全球直连而非游戏平台——后者代理优先，会拖进几十 GB 下载
#   3. 补回它未覆盖的源——否则对应分组变成无规则的孤儿组
#
# 格式：URL<空格>策略名
